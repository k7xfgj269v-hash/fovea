# AI-Native OS

> 把一台 Unix 机器改造成 AI 的「玻璃盒」——人照常用 shell，额外给 AI 一层能全内省、可操作内核的系统接口面。
>
> **状态**：设计阶段（2026-07-07），尚未动手实现。完整设计见 [`docs/DESIGN.md`](docs/DESIGN.md)。

## 这是什么

一个坐在 Unix 之上的特权 daemon（不是新内核，不是厚运行时框架），给 AI operator 暴露一套 **为 token 而非人眼设计** 的系统接口：

- **全内省**：看穿每个进程的线程/内存/fd/调用栈，粒度到运行时的函数（透到运行时边界）。
- **操作内核**：从 eBPF 安全干预，到受控的 LKM 无限改写。
- **安全信封**：让一个会幻觉的操作者安全地拥有 ring0——危险能力关在 eBPF verifier + 宿主侧人审门之后。

最接近的现成参照：**整机级、系统化的 MCP**。

## 为什么

今天 agent 操作 Unix 就是「调 bash、发命令、读 stdout」。但 CLI 每条设计原则都为人眼、不为 token：输出是对齐文本+颜色、能力靠 `man` 记、状态隐式、副作用不可逆、报错是散文。本项目把这些逐条翻转成 AI 友好的接口面。

## 核心设计公理

1. 玻璃盒坐在 Unix 上，人机双通道，不是新内核。
2. 具名 verb 占比 = AI-native 程度的刻度。
3. eBPF = 不可靠 operator 的内核态安全信封；LKM 走人审门。
4. AI 定策略、eBPF 执行；AI 不在内核快路径环路。
5. 默认零探针 + 低扰动飞行记录仪。
6. overhead 可解到可忽略；heisenbug 只能压不能消。
7. VM 边界 = 信任边界；可信控制面（审计/门/仲裁）坐宿主侧，门只管加载、管不了运行时。
8. 人永远优先，牙 = 干净拆除 + 分层回滚；对已 commit 副作用，阻止继续 ≠ 回溯撤销。
9. 玻璃盒对人默认半透明，靠「意图审计恒开 + 干预类被动可发现 + 一键拆除」修回准透明。
10. LKM 侧信任边界在参数不在代码：审参数 ≫ 审生成的 C。
11. 内省是 best-effort、会撒谎；价值在「它告诉你它有多不确定」——置信度是一等输出。
12. 看穿到运行时边界为止，不是看穿一切；managed runtime 优雅降级而非失明。
13. 安全脚手架永远先于写能力落地；绝不让写能力 predate 它的容器（含事前门 hook，不只事后审计/拆除）。
14. verifier ≠ 授权门：证明「不崩」不证明「该做」；干预类写能力事前控制 = verifier + 人审门两道。
15. 静默污染分读写两侧：读侧靠置信度可缓解，写侧（干预语义幻觉）部分可缓解、不可根治。

## 里程碑速览（M0–M9，安全脚手架先于写能力）

| 里程碑 | 做什么 | 证明了什么 |
|---|---|---|
| M0 | VM harness：宿主+靶机、vsock、savevm/loadvm、gdb stub | 基座能跑、能秒回滚、能调内核 |
| M1 | 只读 `introspect(pid)` Level 0：/proc + blazesym，零探针 | 投影成立（GB maps → 十几行） |
| M2 | MCP front：introspect 包成 MCP tool + 自描述目录 | 能力面形态成立 |
| M3 | introspect Level 1 views + cost_hint + 置信度 | 投影/分页/成本可调度 |
| M4 | 飞行记录仪：常驻 ring buffer，极低扰动 | 瞬态事件抓得到 |
| **M5** | **宿主侧审计 sink + 仲裁器（人优先 + flush 拆除）+ 干预门 hook** | **安全脚手架（含事前门）——在任何写能力之前** |
| M6 | eBPF 观测通道：按需挂探针 + 效果审计 | 读侧完整 |
| M7 | eBPF 干预通道（override/丢包）+ 被动可发现 | 第一个写能力，verifier 兜底 |
| M8 | fs 事务：dry-run diff + 定点回滚 | fs 写可预览可撤 |
| M9 | LKM 参数化原语模块 + 人审门 | 最后、最危险、参数化 |
