## 1. 概述与定位

### 1.1 一句话定义

把一台 Unix 机器改造成 AI 的**「玻璃盒」**——底层仍是 Unix、人照常用 shell/GUI，额外做**一层给 AI 的系统接口面**，让 AI 能 **全内省（看穿到运行时边界）+ 操作内核（在安全信封内改）**。

- 它**不是**新内核，也**不是**在 Linux 上叠一个厚运行时框架。
- 它是坐在 Unix 之上的 **guest-agent + host-supervisor 两半**：人走 shell，AI 走 daemon，两条通道共享同一台真机的状态；**信任边界 = 宿主 / 靶机边界**。
- 最接近的现成参照：**整机级、系统化的 MCP**（现有 MCP 是零散的 per-tool；这里要覆盖 fs/proc/net/pkg/job/事务/内核内省一整套，还要吃下 Unix 生态长尾）。

> 范围诚实：是「看穿到**运行时边界**」，不是字面「看穿一切」。托管运行时（V8/JVM/LuaJIT）内部按优雅降级处理，见 §11。

### 1.2 三种读法，选了哪个

「给 AI 用的 OS」指向三个完全不同的项目：

1. **AI 是使用者（operator）** — OS 的「用户」不再是人而是 agent，为 LLM 重新设计感知/决策/执行接口。 ← **选这个**
2. AI 是负载（workload） — 跑推理/训练，GPU/显存/算子一等公民，本质 HPC。
3. AI 是内核决策者 — 用学到的策略替换 OS 启发式（调度/换页），偏 paper。

**收窄链**：operator 视角 → 不重写内核、不叠厚运行时 → 一层薄的 AI 友好接口面 → **下沉到内核级的内省 + 操作**。

### 1.3 皇冠明珠：真正的新问题在哪

工程直觉容易把重量压在「内核内省」（§4–7）上，但内省——按本文自己的划分——是「不 AI 特有、绕不开的**已知**硬骨头」。真正新、真正难的是两件事，设计重量应往这两处挪：

1. **上下文虚拟化 / 投影**：内核状态是海量的（进程内存 GB 级、ftrace 几百万条、kcore 是整个内核内存），AI 上下文装不下。难点不是抓数据，是喂之前「此刻该看什么」的投影。这个问题在 §2.1 以「稀缺资源」、在 §6 以「上下文爆炸」**出现两次——是同一个问题**，是全篇皇冠明珠。§10 的 `introspect(pid)` 就是把它逼到一个可解的小面上。
2. **怎么安全地共享一台真机**：人和 AI 共用同一台真机，而 AI 手握 kcore + 内核写能力。信任边界、仲裁、透明性、审计一整套（§8）由此而来。

## 2. 核心心理模型

### 2.1 稀缺资源变了

传统 OS 的抽象都围绕 1970s 两个稀缺资源生长：**CPU 时间 + 物理内存**。对 agent，稀缺资源换成三样：**上下文窗口（注意力预算）、token 吞吐、钱**。几乎一一对应（注：「钱」的管理机制已定 = 做最小账本，见 §12）：

| 传统 OS | AI OS |
|---|---|
| RAM | 上下文窗口 |
| 虚拟内存 / 换页 | 上下文管理（摘要 / 检索 / 淘汰） |
| 磁盘 | 外部记忆（向量库 / scratchpad / 文件） |
| 进程 / 线程 | agent / subagent 调用 |
| 系统调用 | 工具调用（tool / function calling） |
| 调度器 | 编排器（分配 token/钱 预算，而非 CPU 时间片） |
| 权限 / capability | 工具沙箱 + 审批门 |
| IPC / 管道 | agent 间消息总线 |
| 内核态 / 用户态边界 | 可信 harness vs 不可信的模型输出 |

> 这张表里**只有「上下文虚拟化」是真正内核级、还没被做透的**问题，其余都能在普通 Linux 上做成运行时。它在 §6 又以「上下文爆炸」的名字作为头号 AI 难题出现——**是同一个问题**（§1.3 皇冠明珠）。`introspect(pid)`（§10）把它逼到一个可解小面：一个 pid 的「什么进 level 0、什么藏 handle 后」就是投影策略的最小实例。

### 2.2 POSIX 原则翻转（「对 AI 方便」的准确定义）

现有 shell 对 agent 处处别扭，因为 CLI 每条原则都为人眼、不为 token 设计。逐条翻转：

| POSIX / shell（为人） | AI-native 接口（为 token） |
|---|---|
| 输出对齐文本 + 颜色转义 | 结构化 JSON，可投影（只回要的字段）、可分页 |
| 能力靠人记 / `man` | 自描述：一个 endpoint 吐出全部能力 + schema + 副作用等级 |
| 会话状态隐式（cd/env/后台进程） | 会话状态显式、可查询、可持久化 |
| 副作用即时不可逆（`rm -rf`） | 危险操作能 dry-run 预览 diff、能快照回滚 |
| 报错是散文 + 退出码 | 结构化错误：类型 + 原因 + 建议下一步 |
| 按路径寻址 | 路径 + 可选语义寻址（见 §12） |

## 3. 能力面：两条路线（决定它是不是「又一个 bash wrapper」）

- **路线 A：通用 exec + 结构化输出** — agent 还是拼 shell 字符串，你只把输出/错误/异步/回滚做好。能力无限、零摩擦，但本质是**「更好的 bash 工具」**。
- **路线 B：具名能力 + schema** — agent 调 `fs.find(pattern, project, fields=[...])` 而非拼 `find`。可发现、可校验、可精细授权，但工程量大，搞不好变**「更啰嗦的 shell」**。

**决策：混合，顺序关键** — 先做**逃生舱 `exec`（路线 A + 强制结构化输出 + 显式会话状态）**跑通形态、覆盖长尾；再把高频操作（fs/proc/git/pkg）逐步「提升」成路线 B 的具名 verb。

**分水岭**：如果 agent 最后还在拼 shell 字符串，你做的就是结构化 shell，不是系统调用面。**具名 verb 占比 = 项目 AI-native 程度的刻度。**

> 实现映射见 §13.8：具名 verb 和逃生舱 exec 都落成 MCP tool，每个 verb 带**副作用等级**一等字段（read / dry-runnable-write / irreversible / kernel-write-needs-gate）。

## 4. 下沉到内核：内省 + 操作

### 4.1 「看到每个进程内部函数」的机制

| 机制 | 看到什么 | 层 / 代价 |
|---|---|---|
| `uprobe`/`uretprobe`（eBPF） | 用户态函数入口/出口、参数、返回值，不停进程 | 用户态，低开销 |
| `kprobe`/`fprobe`（eBPF） | 内核任意函数的调用与参数 | 内核态 |
| `ftrace function_graph` | 内核函数调用图 + 耗时 | 内核态 |
| `ptrace` | 停进程、读写寄存器/内存、单步、抓调用栈 | 侵入式（要停） |
| `/proc/<pid>/{maps,stack,wchan}` | 内存布局、当前内核栈、阻塞点 | 快照 |
| `/proc/kcore` + `kallsyms` | 内核内存只读镜像 + 符号地址 | 内核内省 |

引擎 = **uprobe（用户态）+ kprobe/ftrace（内核态）+ 符号化**。

> 注：`uprobe` 看的是**有静态符号的 native 用户态函数**；JIT 运行时生成的代码（V8/JVM 字节码函数、地址运行时才定、无静态符号）这层直接拦住——不是「看用户态函数」一刀切。见 §11 的运行时边界降级。

### 4.2 物理天花板（工程解决不了的硬约束）

1. **全量不可能** — 给每个函数挂探针，进程慢几个数量级。现实永远是选择性挂。
2. **内联优化后函数在运行时不存在** — 被 inline 的函数没有独立调用点，追不到。
3. **strip / 无 DWARF 就只有地址没语义** — 靠 kallsyms、动态符号表或反汇编+函数边界恢复补符号。

> **抓得到 ≠ 喂得进**。这条一句话把皇冠明珠（§1.3）钉死：内省引擎的真正难点在符号化之后的**投影**，不在抓取。

### 4.3 「全暴露」要拆的一排安全墙 → 坐实信任边界

`KASLR`、`kptr_restrict`、`lockdown`、`ptrace_scope`、`CONFIG_STRICT_DEVMEM`、`SMEP/SMAP`。

拆了它们机器对外就是脆的，所以玻璃盒注定活在隔离环境。而拆墙本身，就是「**为什么信任边界必须是硬件/hypervisor 级、而不能是靶机内某个软件门**」的证明：你把靶机内核的自保护全拆了，靶机内**没有任何东西**还能可信地约束 AI，可信的东西只能在墙外（宿主）。信任边界因此坐宿主侧（§8.1）。

## 5. 核心矛盾与解法

### 5.1 eBPF = 不可靠 operator 的内核态安全信封

**矛盾**：既要「给不可靠的 AI 套安全信封」，又要「AI 直接操作内核、全暴露」。这俩在内核态**直接冲突**——内核态没有安全网，一个 AI 幻觉的野指针写入 = 立刻 panic / 文件系统损坏 / 变提权漏洞。

**真问题**：怎么让一个概率性会犯错的操作者安全地拥有 ring0？

**解法 = eBPF**：它让你在内核里跑代码，但有个 **verifier** 在加载前证明这段代码不会崩内核、不死循环、不越界。**这就是「给不可靠代码的内核态安全信封」。** AI 写错 → verifier 直接拒绝；LKM 写错 → panic。

### 5.2 双通道架构（LKM 门 = 审参数不审代码）

| 通道 | 能力 | 安全 | 用途 |
|---|---|---|---|
| **eBPF** | 观测 + **有限**干预（改返回值、丢包、override syscall） | verifier 兜底 | 默认通道，AI 自主 |
| **LKM** | **无限**改写内核数据结构 | 零安全网 | 走人审门 |

> **LKM 门的信任边界在参数、不在代码。** 让人 review 一段 AI 生成的、要算 struct 偏移再写内核内存的 C，正是「看起来没问题、加载后 panic 或**静默污染**」的重灾区；§6 第二层那个「合法但逻辑错误」的问题，在无 verifier 的 LKM 侧后果数量级放大。
>
> 所以 LKM 侧**不让 AI 生成任意 C**，而是 **AI 给一组人写好、审过、编译好的原语模块传参**。审「参数」远比审「生成的 C」强。前提是先枚举「真的只能靠 LKM」的操作集合（§5.3）——它比直觉小得多，而且在缩小。

### 5.3 真正「只能靠 LKM」的操作子集（枚举）

eBPF（含 helper/kfunc/struct_ops）现在能覆盖的很多。真无限改写还得 LKM，但**残余集合是可枚举的、有限且相对稳定**（别指望它随内核演进收缩——eBPF 的设计哲学就是守着「不给任意内核内存写」这条线，那**正是它和 LKM 的本质分界**；`bpf_probe_write_user` 这类甚至在收紧。残余可能持平、不会因 eBPF 变强而消失。但「有限且稳定」恰恰是参数化它可行的前提）：

| 需求 | eBPF 能不能？ | 归属 |
|---|---|---|
| 读任意内核内存 | 能（`bpf_probe_read_kernel`） | eBPF |
| 写用户态内存 | 能但受限（`bpf_probe_write_user`，有告警） | eBPF |
| 改函数返回值 | 能（`bpf_override_return`，需 error-injection 允许列表） | eBPF |
| 丢包 / 改包 | 能（tc/XDP） | eBPF |
| 挂钩子改内核行为 | 部分能（`struct_ops`，如 TCP CC / sched_ext） | eBPF（可表达的部分） |
| **写任意内核数据结构（无对应 kfunc）** | **不能** | **LKM** |
| **结构性 patch / hook 内核代码（struct_ops 表达不了的）** | **不能** | **LKM** |

**LKM-only 残余 ≈ 「任意内核内存写 + 无对应 struct_ops 的结构性改动」**。这就是要做成**参数化原语模块**的那一小撮，每个模块人写死可写字段白名单 + 参数 schema，AI 只填参数。

## 6. 技术困难地图（三层）

### 第一层：通用系统编程的硬骨头（不 AI 特有，但绕不开）

- **符号化会退化**：stripped / 静态链接 / **JIT 代码（V8/JVM/LuaJIT 运行时生成机器码，无静态符号）** 让「看到函数」退化成「看到一堆地址」。 → *判定：你能控制编译的（自己代码/自装内核）配好 DWARF+BTF+帧指针即可；控制不了的（JIT/第三方 stripped）工具链救不了，永远是脏活。* → 这条直接催生 §11 的 managed runtime 范围决策。
- **栈回溯难**：现代默认无帧指针，靠 DWARF CFI / ORC / `.eh_frame`，eBPF 里做用户态回溯尤其麻烦。
- **一致性快照 vs 观察者效应**：不停读到撕裂内存；停了扰动时序。**观测即扰动。**

### 第二层：AI 特有的墙（区别于「又一个 bpftrace 前端」）

- **上下文爆炸（头号难题，= §1.3 皇冠明珠）**：进程内存 GB 级、ftrace 几百万条、kcore 是整个内核内存。真正难点是**喂之前的投影/聚合/摘要——「此刻该看什么」**。
- **时间尺度失配**：AI 决策秒级，内核事件纳秒级。铁律：**AI 定策略、eBPF 在内核里自主执行，AI 绝不能待在快路径环路里。**
- **幻觉在可写侧**：verifier 只保证「不崩」，不保证「逻辑对」。AI 幻觉的偏移会加载一个**合法但逻辑错误**的探针，悄悄污染数据/改错东西。 → 这条是 §11 静默污染检测存在的理由。

### 第三层：通道能力边界

见 §5.2 / §5.3。

## 7. 观测侧决策

### 7.1 运行平台：老电脑当宿主，跑 VM 靶机（信任边界，不只是加速）

裸机两个痛：① AI 高频崩内核，每崩一次物理重启，迭代死慢；② 老内核多半 <5.2 没 BTF → CO-RE 失效 → 掉进手写偏移地狱。

**破法**：老电脑当宿主 → 里面 **QEMU/KVM 靶机**，AI 操作靶机内核。

- 崩了**快照秒回滚**，还能从宿主 gdb 远程调靶机内核；
- 靶机内核**自己选新的装**，BTF/CO-RE/现代 eBPF 白拿，躲开偏移地狱；
- **VM 边界不只是迭代/兼容红利，它是信任边界**（§8.1）：审计 sink、人审门、仲裁器全部坐宿主侧，靶机内 AI 够不着。
- **Intel PT**：KVM 有 `kvm_intel.pt_mode`（`PT_MODE_HOST_GUEST`=1 那档，guest 内用 PT 支持），靶机内做 PT **未必**要退回裸机。很挑内核/硬件版本，**M0 里实测确认**——它直接决定「留裸机做最终验证」这条退路要不要留。

### 7.2 惰性内省：按需 + 飞行记录仪（两级）

**原则：默认零探针**。「只在需要时才 grep」一箭双雕：既解上下文爆炸（要什么查什么），又是观测扰动第一道防线（**不挂的探针没有 probe effect**，扰动基线为零）。

**死角 = 瞬态事件**（崩溃前那串调用、偶发 race 那一刻）。补法 = **两级结构**：

- **飞行记录仪**：低开销、始终在跑（perf 采样 + eBPF 只往 ring buffer 记聚合计数/最近 N 条，像黑匣子）；
- **触发深挖**：AI 要看 / 出异常时，回放这个环 + 挂详细探针。
- 关键：飞行记录仪必须**极低扰动**，否则常驻白搭。
- **「按需 grep + 飞行记录仪 + 观测扰动」收敛成同一个设计。**

> **同构**：写侧审计（§8.4）之于人，就是飞行记录仪之于 AI——**同一个物理问题（瞬态事件，等你反应过来已发生完），同一个解（常驻低开销记录 + 按需深挖消费）**。

### 7.3 观测扰动：二分决定「能不能解」

- **性能扰动（overhead）**：让代码变慢 → **工程可解，压到可忽略。**
- **时序扰动（heisenbug）**：让 race/死锁消失或改变 → **物理不能根治，只能压低。**

**overhead 手段阶梯（便宜 → 贵）**：

1. **按需** — 不采就是零（最有效）。
2. **采样代替全量** — 定时中断抓栈，开销只和采样频率挂钩、与被测调用频率无关。代价：漏低频、无单次精确。
3. **免陷入探针** — 内核用 `fentry/fexit`（BPF trampoline）、用户态用 USDT 静态点，**直接跳转代替异常陷入**，快一个数量级。
4. **内核内聚合** — eBPF map 里做直方图/计数，只传结果（= 上下文爆炸的投影同一招）。
5. **硬件卸载** — Intel PT / ARM CoreSight，专用硬件写执行流到旁路缓冲（开销个位数百分比）。代价：数据量爆炸要事后解码 + 要新 CPU。

**heisenbug 没有银弹**：① 最低扰动组合（硬件 PT + 采样）压到行为不质变；② 测量扰动本身（先跑无探针基线对比）；③ 换范式——从硬件 trace **事后重建**执行流，把观测与运行在时间上解耦。

> **PT 不可用的降级（M0 实测 guest PT 若失败）**：③ 换范式这条**依赖硬件 PT**，PT 没有就塌了，剩 ①+② 里也去掉硬件那半。回退只有软件采样 + 测量扰动——**这一档压不低 heisenbug 到「行为不质变」**。诚实做法：把采样率压到扰动可忽略、多次重跑取交集、并**在契约层承认「时序敏感 bug 在本平台可能观测不到」**。裸机保留 PT 能力（§7.1）因此是 heisenbug 侧的最终退路，不是可选优化。

**收口**：overhead 是工程问题、能解到可忽略；heisenbug 是物理问题、只能压不能消。

## 8. 信任边界、仲裁、透明性

> 「人机双通道共享一台真机」这个前提，逼出信任 / 仲裁 / 透明性一整套问题。双通道并不对称：**它对人只是半透明，要专门修回来。**
>
> 术语：**半透明** = 默认状态（AI→人全透，人→AI 不透）；**准透明** = 装上 §8.5 三件套后修回的状态——**不是「全透明」**，因为运行时行为仍无法全审（§8.1：门只管加载、管不了加载后的运行时），故只能称「准」。

### 8.1 信任边界坐宿主侧（设计公理）

问题：审批门 / 仲裁器 / 审计，在不在 AI 的可触及范围内？AI 手握 kcore + LKM，如果这些东西跑在靶机内，AI 原则上能观测甚至改写**约束它自己的门**（§5 的 eBPF verifier 答案在这层不成立：verifier 保证不崩，不保证 AI 碰不到自己的 gate）。

**决策：一切可信控制面坐宿主侧，VM 边界 = 信任边界。**

代价（明写、接受）：**宿主侧的门只能 gate「加载」这个动作，gate 不了 eBPF/LKM 加载后在靶机内核里的运行时行为**。一段合法通过 verifier、逻辑幻觉的探针，宿主拦不住 → 这个残缺的后果交给 §8.4（效果审计）+ §11（静默污染检测）处理。**永远别假装门能管运行时；门只管入口。**

物理实现见 §13.2：daemon 拆成 guest-agent（靶机内，做内省/挂探针）+ host-supervisor（宿主，做审计/门/仲裁/快照），**信任边界就是这两半之间的 vsock**。

### 8.2 仲裁：人永远优先 + 干净拆除

**规则：人永远优先。** 但「优先」的强度取决于操作处于哪个阶段：

| 阶段 | 「人优先」意味着 | 依赖 |
|---|---|---|
| 操作**未启动** | 人可抢占，AI 那条排队/作废 | 无，直接成立 |
| 操作**在跑**（eBPF 已挂，脱离 AI 决策环自主执行） | 杀 AI 对话**停不了**已挂探针——「人赢」必须含**干净拆除**：一键 flush 掉 AI 所有 BPF 程序/挂载点 | §13.5 probe manager 按 owner=AI 枚举 bpffs pin，原子 detach+unpin |
| 副作用**已 commit**（override 已改了人依赖的返回值） | 回溯撤不掉 | §9 回滚，或接受为残余 |

> **没有干净拆除 + 回滚，「人永远优先」退化成「对没开始的操作人优先」**，弱得多。所以 §8.2 的牙长在 §13.5（拆除）和 §9（回滚）上。
>
> **强度衰减，明写**：把三阶段连起来看，「人永远优先」的实际强度是**递减**的——未启动 = 完全优先（可抢占作废）；在跑 = 优先但需干净拆除才生效（§13.5）；**已 commit = 只剩「阻止继续」，没有回溯**——override 已喂给人的那个返回值撤不回（§9 明列内核态/网络副作用为不可撤残余）。所以「人永远优先」这个承诺，在 commit 之后的诚实说法是「**人能叫停后续，但改不回已发生的**」。别把它读成「人总能把世界拨回去」。

### 8.3 透明性：AI→人全透，人→AI 被动可发现

三个答案（人永远优先 + eBPF 默认通道自主干预 + 可见性默认关）**合起来**产生一个失效：

人在 shell 敲的命令，可能正**穿过** AI 装的某个 `override_return` 探针拿到被改的返回值，而人**没有任何信号**知道这条路径被 AI 插过。仲裁上「人赢了」（命令执行了），但它在 AI 的修改**之下**执行——**赢了执行、输了语义**。对一个卖「对称双通道透明」的系统，这是**透明性反转**：AI→人全透，人→AI 半透。

**修法不是逼人常盯日志（没人盯），是干预类探针「被动可发现」**：

| 探针类 | 改人的现实？ | 视图默认关 OK？ | 要求 |
|---|---|---|---|
| **观测**（uprobe/kprobe 只读） | 否 | ✅ 安全 | 记录恒开即可，视图纯按需 |
| **干预**（override/丢包/改返回值） | 是 | ❌ 不安全 | 无论视图开关，**被动可发现**——人 shell 能随时查「当前 N 个 AI 干预在影响 syscall X/Y」 |

**「非必要不开」的精确含义**：关的是**实时视图/tail**，不是**记录**。记录关掉是 bug——写侧行为和瞬态事件同一个物理问题（§7.2），没记就是永久丢失。**记录恒开、视图按需。**

### 8.4 审计两层（便宜那半正好够用）

| 审计层 | 采集 | 成本 | 回答 |
|---|---|---|---|
| **意图审计** | AI 决定装什么 / 改什么参数，每条 attach/detach/config/参数全记 | 低频、便宜、完整 | 「发生了什么」**主要**靠它 |
| **效果审计** | 探针运行时**实际**干了多少（丢多少包、override 触发几次） | 高频、采样、best-effort | 「实际影响多大」——撞观测量墙 |

> 铁律：**你没法全保真审计一个你没法全保真观测的东西**。意图审计能完整，是因为「意图」低频；效果审计只能采样，因为它是运行时高频流。别把两者混谈。

### 8.5 小结：玻璃盒对人从半透明修回准透明的三件套

1. 意图审计恒开（§8.4），sink 在宿主（§8.1）——AI 改不了自己的账。
2. 干预类探针被动可发现（§8.3）——人默认视图关也能查出活体修改。
3. 干净拆除（§8.2 / §13.5）——人一键收回 AI 对内核的所有挂载。

## 9. 回滚模型：分层

> 「回滚」有两个完全不同的粒度，必须分开：操作级 vs VM 级。

| 层 | 机制 | 粒度 | 代价 | 撤得掉什么 |
|---|---|---|---|---|
| **fs 事务** | 操作前建事务日志 + dry-run diff + 定点撤销 | 单个危险 verb | 中（要建子系统） | fs 写（改文件/删除/移动） |
| **VM 全状态快照** | savevm/loadvm，崩溃兜底 | 整机 | 几乎免费，但回滚**一切** | 内核崩溃、任何靶机内状态（含人 shell 刚做的活 + AI 的记忆） |

**残余（明写进契约、不假装能撤）**：已 commit 的**内核态改动、网络副作用、已 fork 的进程**——语义上未必可撤。VM 快照能把整机拨回去，但那是核弹级（连人的活一起没），不是精细撤销。

**决策**：

- fs 走事务（精细、可选择性撤）；
- 内核态崩溃走 VM 快照兜底（粗、灾难恢复）；
- 其余不可撤副作用 → 契约层标「irreversible」，靠 §8.2 干净拆除**阻止继续**，而非回溯撤销。

> dry-run diff 属于 fs 事务层，快照属于 VM 层，**它俩不是一个东西，别指望一个机制同时给你精细 diff 和整机秒回**。

## 10. `introspect(pid)`：内省引擎第一个原语

设计成**投影优先 / 惰性 / 分层**，而不是一次吐全息。一箭三雕：① 纯 `/proc` + 符号化、**零探针**只读快照，坐实「只读全息先行」；② 给一个 pid 定「什么进 level 0、什么藏 handle 后」的边界，**就是在小尺度上写投影策略**（皇冠明珠逼到可解小面）；③ 不挂探针 → 天然低扰动。

```
introspect(pid) -> Level 0，恒定小体积，纯快照，零探针
  identity   : pid/comm/exe/cmdline(截断)/uid/cgroup
  state      : R|S|D|Z, last_cpu, nr_threads,
               wchan(符号化的阻塞点)     ← 单位 token 语义密度最高，D 态几乎直接答「卡在哪」
  resource   : RSS/VSZ, fd 数, %cpu(短采样), ctxt-switch 计数
  mem_shape  : 区段直方图 —— 按 kind(heap/stack/anon/file/x-lib) 聚合的 {count,total_size}
               + top-N 大映射；绝不吐完整 maps 表   ← GB 级 maps → 十几行，这就是投影本体
  hotspot    : D 态时给内核栈顶 3–5 帧(符号化 + 每帧置信度)  ← 「为什么卡」压进 5 个符号
  recent     : 该 pid 最近 N 条飞行记录仪聚合事件(若记录仪在跑)  ← 复用常驻记录仪，非本调用新增探针；见下方「零探针」精确定义
  confidence : 本次快照整体可信度摘要(见 §11)
  handles    : { threads, maps, stack:per-tid, fds, env, symbols }  ← 不透明游标，按需展开
  cost_hint  : 本次调用成本估计 {token, api_cost?, overhead_est}(§12 账本已定)

introspect(pid, view=maps|threads|stack|fds, cursor=…, fields=[…], page=…) -> Level 1
  每个 view 可投影(fields=)、可分页；栈的 DWARF/ORC 回溯成本只在 view=stack 时才付
```

**钉死的三条断言**：

1. **每次返回带 cost_hint**（level 0 ≈ 免费；`view=stack` 付回溯；挂探针根本不是 introspect 该干的事，那是另一个原语）——让 §2.1「编排器 = 分配 token/钱预算的调度器」有东西可调度。
2. **wchan + 内核栈顶优先级最高**，进 level 0 而非藏 handle 后：便宜、语义密、还是 D 态诊断银弹。
3. **每个符号带置信度**（§11）：DWARF 命中 / kallsyms 命中 / 纯反汇编恢复，可信度差数量级，不标 = 把幻觉当真值喂。

**「零探针」的精确含义**：指 introspect 本次调用**不新增任何探针、不 ptrace、不对目标进程施加新扰动**——纯读 `/proc` 文件。`recent` 字段是唯一的复用来源：它读的是常驻飞行记录仪（若已开）的数据，那是**系统级常驻探针，不是本调用引入的**。所以 Level 0 对目标进程的**增量扰动为零**；`recent` 的存在只依赖记录仪自身的低扰动预算（§7.2），不改变「本调用零新增扰动」这个承诺。§13.4 的「零探针零 ptrace」按此理解——是「零新增」，不是「系统里没有任何探针」。

**managed runtime 下的优雅降级**（§11 决策 A 的具体表现）：一个卡死的 Node，level 0 照样看到它阻塞在某个 native syscall 上，wchan + 内核栈顶正常给；丢的只是「哪个 JS 函数触发的」。**不是整个失明，是透到运行时边界为止。**

## 11. 静默污染与地面真值

> 一个卖「看穿一切」的系统，最致命的失效模式**不是崩溃**——是**它自信地喂给你幻觉偏移读出来的错数据，而没有任何信号告诉你它错了**（§6 第二层「合法但逻辑错误」）。必须有检测机制。

**managed runtime 范围决策（Q4）**：选 **A——只声称看穿 native + 自装内核，托管运行时（V8/JVM/LuaJIT）按「透到运行时边界」处理**（基座 native 栈/syscall/wchan 可见，内部 JS/字节码函数不保证）。B（每运行时插件：perf-map-agent / async-profiler / py-spy）做成**可选能力包**，不是核心承诺。理由：A 跟 §6「工具链救不了 JIT」一致且诚实；把 B 塞进核心承诺，质量会随运行时版本漂移。**对外别说「黑箱」，说「透到运行时边界」——别自己把 thesis 说小。**

**地面真值三招（研究机档位：② + ③ 打底，① 对高价值字段做）**：

| 招 | 做法 | 用在哪 |
|---|---|---|
| ① **双路交叉验证** | 同一事实两条独立路径比对（如 wchan 符号化结果 vs `/proc/pid/stack` 顶帧是否自洽） | 高价值字段（wchan / 阻塞点） |
| ② **符号化置信度标注** | DWARF 命中 / kallsyms 命中 / 动态符号 / 纯反汇编恢复，分级打分进返回 | 所有符号化输出 |
| ③ **契约层明写** | 「只读内省是 best-effort、可能撒谎」写进 introspect 契约，不默认为真 | 全局 |

**决策**：置信度（②）进 introspect（§10）每个符号；wchan 这种诊断银弹字段加双路交叉（①）；全局契约标 best-effort（③）。研究机不追求内省绝对正确，追求**内省会告诉你它有多不确定**——这是个明写的决定，不是默认沉默。

### 11.1 范围限制：以上只覆盖「读侧」，写侧是真实缺口

**明写：§11 到此为止只解决「读侧」静默污染**——内省读出来的数据可不可信。它**没覆盖写侧**：一个 AI 装的 `override` 探针，改对了返回值类型、过了 verifier、但**语义错了**（§6 第二层「合法但逻辑错误」）。置信度管的是符号化输出，**不管干预的语义对不对**；效果审计（§8.4）量化的是**触发频次**，不是**语义正确性**。这个洞在 M7 写能力落地时会显形。

**写侧方向（尚未解决，只有种子）**：override/干预探针加载前，在**历史飞行记录仪 trace 上 dry-run 抽样**——用过去的真实调用喂给这段探针，看它产出的改动分布是否偏离预期基线。局限必须同样明写：① 历史 trace 未必覆盖未来场景；② 「预期基线」本身要人或 AI 给，可能也是错的；③ **dry-run 能抓「明显离谱」，抓不住「微妙语义错」**。所以写侧静默污染当前的诚实状态是：**部分可缓解、不可根治，比读侧更难**。列入 §15 未决，M7 前专门设计。

## 12. 悬空点收口：钱 + 语义寻址

> 两个点已按推荐拍板落定。

**钱 → 决策：做最小账本（已定）**。introspect 已吐 cost_hint（token 侧），把它扩成一个 host-supervisor 持有的**运行账本**：每次 AI 调 verb / 挂探针 / 调付费 API 记一笔（token 消耗 + API 花销 + 探针常驻 overhead 折算）。编排器（§2.1）读它做预算调度。于是 §2.1 的「钱」从悬空的一等公民落成**有机制的一等公民**，`cost_hint` 形状随之固定为 `{token, api_cost?, overhead_est}`。

**语义寻址 → 决策：降级为 tag 寻址（已定）**。基座只做「路径 + 可选 tag/标签寻址」（便宜、确定）；嵌入式语义索引（向量化）是大子系统、不在关键路径，**推迟到后期能力包**——introspect / 双通道 / 审计跑通之前不碰。若日后要把它当核心差异化能力，单独立项，别混进基座。

## 13. 实现蓝图：怎么写

> 给 shape、选型、拓扑、生命周期、构建顺序。

### 13.1 技术栈选型（带理由）

| 组件 | 选型 | 理由 |
|---|---|---|
| **daemon 语言** | **Rust** | ① 控制面不能有 GC 停顿；② 内存安全——最不该崩的那个组件（可信 harness）不该用最不安全的语言写，C 在这里讽刺；③ eBPF 生态成熟；④ tokio 处理并发的 请求/tail/审计 流 |
| **eBPF 加载** | **libbpf-rs**（CO-RE via BTF） | 成熟 + CO-RE 经过验证。备选 aya（纯 Rust、免 clang 运行时依赖）更年轻，CO-RE 可靠性优先选 libbpf-rs |
| **符号化 + 回溯** | **blazesym**（libbpf 组织出品） | 统一处理 ELF/DWARF/kallsyms/gsym + DWARF/ORC 回溯。**这是最重要的库选择——符号化质量 = 内省质量（§4.2）** |
| **BPF 程序** | C + clang → BPF 字节码，CO-RE 重定位到靶机 BTF | 标准 CO-RE 路线，躲偏移地狱 |
| **对 AI 线格式** | **JSON**（可投影、可分页，§2.2） | 内部用 Rust 强类型，出口序列化成 JSON |
| **AI ↔ daemon 传输** | **MCP**（§1.1），stdio 或 SSE | daemon 本身就是个 MCP server |
| **宿主 ↔ 靶机控制通道** | **virtio-vsock** | 不走靶机网络（AI 能搞网络），host↔guest 直连，审计 ship + 命令下发都走它 |
| **VM** | **QEMU/KVM** | 全状态快照 savevm/loadvm、`-s -S` gdb stub、`kvm_intel.pt_mode=1` 试 guest PT |

### 13.2 进程拓扑：guest-agent + host-supervisor（信任边界的物理实现）

**daemon 不是一个进程，是两半，信任边界就是这两半之间的 vsock**（§8.1 的落地）：

```
┌─────────────────── 宿主机（可信侧） ───────────────────┐
│  host-supervisor (Rust)                               │
│   ├─ 审计 sink（append-only，意图+效果）  ← AI 够不着  │
│   ├─ 人审门（LKM 参数审批）                            │
│   ├─ 仲裁器（人永远优先 + 触发干净拆除）               │
│   ├─ VM 快照控制（QMP: savevm/loadvm）                 │
│   └─ 人的 shell / 审计 tail 视图（按需开）             │
│                         ↑ virtio-vsock（= 信任边界）   │
└─────────────────────────┼─────────────────────────────┘
┌─────────────────── 靶机 VM（不可信侧） ─────────────────┐
│  guest-agent (Rust)                                   │
│   ├─ MCP front（能力面：具名 verb + 逃生舱 exec）      │
│   ├─ 内省引擎（introspect：/proc + blazesym，零探针）  │
│   ├─ probe manager（eBPF 生命周期 + flush 拆除）       │
│   ├─ 飞行记录仪（常驻 ring buffer 消费）               │
│   └─ 写侧（eBPF 干预 + LKM 原语模块加载）              │
│  靶机内核（自保护墙全拆，§4.3）                        │
└───────────────────────────────────────────────────────┘
```

**关键**：guest-agent 需要贴着靶机内核（挂探针、读 kcore），所以它在靶机内、**不可信**；可信的东西（审计/门/仲裁）全在宿主。AI 即便完全接管 guest-agent，也改不了已 ship 到宿主的审计、绕不过宿主的门。

### 13.3 组件分解 + 可靠性梯度

把组件按「可靠性要求」分两个平面，梯度直接映射到「谁在信任边界哪一侧」：

| 平面 | 组件 | 可靠性要求 | 位置 |
|---|---|---|---|
| **控制面** | 审计 sink、人审门、仲裁器、probe manager、VM 快照 | 极高（不能是崩的那个） | 审计/门/仲裁/快照在宿主；probe manager 在靶机但逻辑简单可测 |
| **数据面** | 内省引擎、飞行记录仪、写侧执行 | best-effort（高量、可能撒谎） | 靶机 |

> 设计原则：**控制面小、简单、可穷尽测试；数据面高量、best-effort、带置信度**。别让数据面的复杂度渗进控制面。

### 13.4 `introspect` 具体 schema

见 §10。实现要点：Level 0 全部来自 `/proc/<pid>/{stat,status,maps,wchan,stack,fd/}` 解析 + blazesym 符号化，**零探针零 ptrace**（纯读文件，对目标进程连观察者效应都没有）。**唯一例外**：`recent` 字段复用常驻飞行记录仪数据（见 §10「零探针」精确含义），是「零新增」而非「系统无探针」。`mem_shape` 直方图在 agent 内聚合 maps（GB 级 maps 表 → 十几行按 kind 的 {count,total}），**这一步就是投影本体，别把原始 maps 往 AI 送**。

### 13.5 eBPF 生命周期与「flush」拆除（§8.2 的牙）

```
加载：  BPF-C → clang → CO-RE 重定位(靶机 BTF) → verifier → attach
登记：  程序/map pin 到 bpffs，但在 probe manager registry 里带
        { owner=AI, ts, purpose, class=观测|干预, affects=[syscall/fn...] }
拆除：  probe manager 能按 owner=AI 枚举所有 pin，原子 detach + unpin
        ← 这就是「人赢」的干净拆除；人一键收回 AI 全部内核挂载
审计：  每次 attach/detach/config → 意图审计一条(ship 到宿主 sink)
可发现：干预类(class=干预)的 affects 字段，喂给人 shell 的「当前干预查询」(§8.3)
```

**干预类必须在 registry 里显式标 `affects`**，否则 §8.3 的「查当前 N 个干预影响哪个 syscall」无从实现。

### 13.6 宿主侧审计 sink（vsock）

- **append-only**，格式 JSON lines（可 grep 可投影，符合全篇 token 友好基调）或二进制日志 + 索引。
- guest-agent 把审计事件**经 vsock ship 到 host-supervisor**——不走靶机网络、不落靶机磁盘（AI 都能碰），已 ship 的宿主侧记录 AI 改不了（§8.1）。
- **两流分开**：意图流（每个决策，完整）+ 效果流（采样运行时统计）。别混进一个 schema。

### 13.7 VM 靶机搭建

```
qemu-system-x86_64 \
  -enable-kvm -cpu host \
  -kernel <靶机自选新内核, 5.x+ 带 BTF> \
  -device vhost-vsock-pci,guest-cid=<N> \     # 控制通道
  -s \                                         # gdb stub :1234，宿主调靶机内核
  ...
# 全状态快照：QMP 下 savevm/loadvm(崩溃秒回滚，§9 VM 层)
# Intel PT：启动前试 modprobe kvm_intel pt_mode=1，M0 内实测 guest PT 可用性(§7.1)
```

靶机内核**自己装、配好 CONFIG_DEBUG_INFO_BTF + CONFIG_UNWINDER_ORC + 帧指针**——这是「你能控制编译的就配好」（§6 第一层）落地的地方。

### 13.8 MCP 能力面映射

- 每个具名 verb（`fs.find`、`proc.introspect`…）= 一个 MCP tool + JSON schema。
- 逃生舱 exec = 一个 MCP tool，输出强制结构化包装（stdout/stderr/exit/耗时/会话状态 delta）。
- **自描述** = 一个 MCP tool 吐全能力目录 + 每个 verb 的**副作用等级**一等字段：

  | 副作用等级 | 含义 | 门 |
  |---|---|---|
  | `read` | 纯读（introspect Level 0） | 无 |
  | `dry-runnable-write` | 可预览 diff 再执行（fs 写） | dry-run → 确认 |
  | `intervention` | eBPF 干预（改现实） | **事前**：verifier（仅挡崩溃、不挡语义）+ 干预门 hook（M5 起在位，默认放行、可切人审）；**事后**：效果审计 + 被动可发现（§8.3）+ 干净拆除。注意 verifier ≠ 授权门——它证明「不崩」，不证明「该做」 |
  | `kernel-write` | LKM 原语模块 | **人审门（参数，§5.2）** |
  | `irreversible` | 不可撤（§9 残余） | 显式确认 + 审计 |

- 会话状态（cd/env/后台 job）= 显式、可查询、可持久化的对象（§2.2），不是隐式进程状态。

### 13.9 构建顺序 / 里程碑（安全脚手架**先于**写能力）

> 排序原则：**先便宜地证明形态，后置昂贵/危险的；安全脚手架必须早于任何写能力**——绝不让写能力先于它的容器存在。

| 里程碑 | 做什么 | 证明了什么 |
|---|---|---|
| **M0** | VM harness：宿主+靶机、vsock 通道、savevm/loadvm、gdb stub 全通；实测 `kvm_intel.pt_mode` | 基座能跑、能秒回滚、能调内核（还没 AI） |
| **M1** | 只读 `introspect(pid)` Level 0：`/proc` + blazesym，零探针 | **投影**成立（GB maps → 十几行）——皇冠明珠第一刀 |
| **M2** | MCP front：把 M1 包成 MCP tool，结构化输出 + 自描述目录 | AI 能调 introspect；能力面形态成立 |
| **M3** | introspect Level 1 views + cost_hint + 置信度 | 投影/分页/成本可调度（§2.1 编排器有料可调） |
| **M4** | 飞行记录仪：常驻 ring buffer，极低扰动 | 瞬态事件抓得到（§7.2） |
| **M5** | **宿主侧审计 sink（意图审计）+ 仲裁器（人优先 + flush 拆除）+ 干预门 hook（拦干预类 attach，默认放行、可切人审）** | **安全脚手架就位（含事前门）——在任何写能力之前** |
| **M6** | eBPF 观测通道：按需挂探针 + 效果审计 | 读侧完整（观测类，只读，视图按需） |
| **M7** | eBPF 干预通道（override/丢包）+ **被动可发现** | 第一个写能力，verifier 兜底，带 §8.3 可发现 |
| **M8** | fs 事务：dry-run diff + 定点回滚 | fs 写可预览可撤（§9 事务层） |
| **M9** | LKM 参数化原语模块 + 人审门 | 最后、最危险、参数化（§5.2/§5.3 枚举集） |

**M5 的位置是全篇安全 thesis 的落地**：审计 / 仲裁 / 拆除 / **事前干预门** 必须建在 M6+ 任何写能力之前。

**为什么 M5 必须含「事前」门**：只有审计 + 拆除是**全事后**能力；M7 的 eBPF 干预若只靠 verifier（自动放行）+ 被动可发现（事后），那么它落地时**没有任何人可介入的事前门**——公理 13 就只是**形式成立、实质缺口**。所以 M5 要注册一个事前 hook：拦截干预类 attach，**默认放行、可一键切人审**。它默认是 no-op，价值在**架构位置在位**——M7 伸手时，事前那道栅栏已经存在，只需拨开关。**你先造牢笼——含事前那道栅栏——AI 才被允许伸手。别让任何写能力 predate 它的容器。**

## 14. 设计公理

1. 玻璃盒坐在 Unix 上，人机双通道，不是新内核。
2. 具名 verb 占比 = AI-native 刻度。
3. eBPF = 不可靠 operator 的内核态安全信封；LKM 走人审门。
4. AI 定策略、eBPF 执行；AI 不在快路径环路。
5. 默认零探针 + 低扰动飞行记录仪。
6. overhead 可解、heisenbug 只能压。
7. VM 边界 = 信任边界；一切可信控制面（审计/门/仲裁）坐宿主侧，门只管加载、管不了运行时。
8. 人永远优先，但「优先」的牙 = 干净拆除 + 分层回滚；对已 commit 副作用，阻止继续 ≠ 回溯撤销。
9. 玻璃盒对人默认半透明，靠「意图审计恒开 + 干预类被动可发现 + 一键拆除」修回准透明。
10. LKM 侧信任边界在参数不在代码：审参数 ≫ 审生成的 C。
11. 内省是 best-effort、会撒谎；价值在「它告诉你它有多不确定」——置信度是一等输出，不是可选装饰。
12. 看穿到运行时边界为止，不是看穿一切；managed runtime 优雅降级而非失明。
13. 安全脚手架永远先于写能力落地（M5 先于 M6+）；绝不让写能力 predate 它的容器——**容器含事前门 hook（默认放行、可切人审），不只事后审计/拆除**。
14. verifier ≠ 授权门：它证明「不崩」，不证明「该做」；干预类写能力的事前控制 = verifier（挡崩溃）+ 人审门（挡语义/授权）两道，缺一不可。
15. 静默污染分读写两侧：读侧靠置信度可缓解，**写侧（干预探针语义幻觉）部分可缓解、不可根治**，别当已解决。
